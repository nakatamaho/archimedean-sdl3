# Specification

## Purpose

`archimedean-sdl3` demonstrates all 13 Archimedean solids using polygon data generated by SageMath and displayed by a portable SDL3 viewer.

## Architectural split

### Geometry pipeline

SageMath -> canonical polygon topology -> deterministic JSON -> pure-Python validation.

### Viewer pipeline

JSON -> validated model -> CPU 3D transform -> face culling -> flat Lambert shading -> polygon fan triangulation -> depth sort -> perspective projection -> SDL3 `SDL_RenderGeometry()`.

The viewer must never depend on SageMath at runtime.

## Geometry tolerances

Document actual chosen values beside the implementation. Initial targets:

- normalized edge spread: <= `1e-8` relative where practical, otherwise justify a looser threshold for approximate Sage constructors;
- face planarity: <= `1e-9 * characteristic_radius` where practical;
- vector normalization zero threshold: `1e-12`.

Do not silently widen a tolerance to make failing data pass. Record why a change is necessary.

## Viewer behavior

The solid continuously rotates using elapsed time. The user can edit the normalized rotation axis and angular speed while the program is running. Each polygon is opaque and flat-shaded.

For a convex solid, v1 uses back-face culling plus back-to-front visible-face sorting instead of a hardware depth buffer. If a concrete artifact demonstrates incorrect occlusion, replace this renderer in a later milestone; do not preemptively introduce a platform-specific graphics API.

## Error handling

Startup must fail clearly on:

- missing JSON;
- malformed JSON;
- unsupported schema version;
- missing requested solid;
- invalid vertex index;
- non-finite coordinate;
- topological inconsistency detected by the runtime loader.

SDL errors must include `SDL_GetError()` text where relevant.
